Know your caller.
Cryptographic proof, not promises.

v4call is paid, end-to-end-encrypted voice, video, screen-share and chat that uses the Hive blockchain as a phonebook. Every message and call is signed and encrypted in your browser to the receiver’s public key — the server can’t read it, and the person on the other end has cryptographically proven they hold the private key for the username that contacted you.

Open the demo on this server → Run your own server

Other live test servers (currently federated): v4call.com · hive-book.com · call.completenoobs.com

What v4call gives you

Identity

Hive username as your address

Hive accounts come with key pairs. v4call uses the posting public key from the chain to encrypt messages; only the holder of the matching private key can decrypt. No phone numbers, no email.

Anti-spam

Pay to contact, refundable

You set a rate per call type. Anyone outside your allow-list pays your rate from escrow before they can ring you, invite you to a room or DM you. Refundable on missed call or decline.

Sovereignty

MIT licensed, self-hostable

Run it for your domain — call.example.com — with a Docker compose file. Federate with other v4call servers if you want, or stay local.

Encryption, in one paragraph. Text messages are encrypted in your browser to each selected recipient’s posting public key (pulled from Hive). Voice, video and screen sharing ride on WebRTC, which has its own end-to-end encryption between peers. Your active Hive key is only ever used by Hive Keychain in your browser to sign payment transactions — the server never sees it.

Step 1 — get a Hive account

A Hive account costs 3 HIVE to register on-chain (this exists to slow down spam). There are several services that will create one for free; the one currently used for testing is signup.hive.io.

A hosted onboarding service called hive-gate is on the roadmap so that v4call operators can offer one-click signups to their users.

Step 2 — log in

Log in with your Hive username and your posting private key. The posting key is the right level of authority for messaging — it cannot move funds.

The key stays in your browser’s memory for the session; it is used locally to decrypt incoming messages and to sign outgoing ones. The server never receives the private key.

Step 3 — the main layout

After login you land in the lobby. The lobby is local to the server you logged in on; rooms, calls and DMs work across the federation.

Default main page after login

Lobby — gated by conditions you set

The lobby is a single public chat on each server. An admin can set conditions for posting — for example, “account must hold at least 10 CNOOBS tokens”. By design the lobby is local-only; it does not federate.

Example: only accounts holding 10+ CNOOBS can post. noblemage passes; testin (4 CNOOBS) does not.

Rooms — ephemeral, encrypted, exportable

A room is ephemeral. If every user leaves, the room and its history are gone. Anyone joining later can only read messages that were encrypted to their key.

A room can be exported and later imported into a new room. Because the messages were encrypted per-user, a third party who imports the file still cannot decrypt anything that wasn’t addressed to them.

One button changes everything. In a room you can either:
  • Toggle on specific users → Send. Only those users can decrypt the message.
  • Press “All”. The message goes out unencrypted to the whole room.
If 10 people are in the room and you toggle on 3 before pressing Send, only those 3 receive a decryptable copy. Export the room later and the same 3 are still the only ones who can read the history.

File transfer — IPFS, your choice of provider

v4call itself does not store any files. User-to-user media (pictures, audio, video, text, PDFs) is uploaded to an IPFS pinning service that you choose. Today there are two compatible options: Pinata (easy, free 1 GB tier) and IPFS-Gate (self-hostable, Hive-payment-gated).

Missed-call refund

If you set a ring rate, callers pay the fee from escrow before their call rings you. If the call never connects — you were offline, or you simply didn’t answer — you see a missed-call alert with two choices: refund the caller, or keep the ring fee.

Announce yourself — one signed Hive post

User-announce generates and posts your v4call conditions to the Hive blockchain. It is one signed Hive post that every app can read — v4call rates, paid-invite offers, Nostr keys, Bitcoin / Lightning addresses, SSH key, contact details. Tick only the sections you want; the rest emit no block at all.

The post title is always user-announce; tags are user-announce, hive, v4call, nostr, bitcoin. Each section is its own versioned block, so apps read what they understand and ignore the rest. Apps always read your most recent post with that title.

The user-announce screen — sections on the left, generated Hive post body on the right

IDENTITY (always in the post)

Enter your Hive username. If the Hive Keychain extension is installed, you’ll see a green “Post to Hive enabled” confirmation under the field. The username appears in every post, so this block can’t be turned off.

V4call service

This block tells readers which v4call server you call home and which escrow account that server controls — the account where your paid calls, DMs and invites settle. Today the live test servers are v4call.com, hive-book.com and call.completenoobs.com; all three currently share the escrow account v4call-escrow.

There isn’t yet a standard federation-hosting rule for the escrow account — that’s on the TODO list.

V4call — set your rates for callers

Expand this section and tick the include checkbox on the right of the title to add the rates block to your post.

Empty rates section — no tokens added, no custom lists yet

This block tells callers what they pay you for each kind of contact: invite fee, offer fee, DM fee, plus voice and video (ring / connect / per-hour rate / minimum deposit). Any field left at 0 means free.

Priority is the order on screen — the resolver walks the list top-to-bottom, and the first match wins:

  1. [BLOCKED] (pinned first) — security gate. Comma-separated usernames go in USERS; if blank, nobody is blocked. Set an optional BLOCK MESSAGE the blocked caller will see. ALLOW-IF-TOKEN is a bypass — if the caller holds the named token, the block does not apply.
  2. Middle rules — your token rates and any custom lists, in the order you drag them. Drag the ⠇⠇ handle to reorder. First match wins.
  3. [LIST:default] (pinned last) — the last-resort fallback that catches everyone else.

A WHO PAYS WHAT tester at the bottom resolves a sample caller against your live order before you post, so you can see who would pay what without committing anything to chain.

Token rates

Inside the priority list you can add token-specific pricing. Click + Add token to open a token block.

A token block — SYMBOL, bypass-block toggle, and the full fee schedule for callers paying in that token

Enter the token SYMBOL. The bypass block checkbox lets holders of this token through the [BLOCKED] gate above. Then set the per-token fees (invite / offer / DM / voice / video). You can add more than one token block — one for each currency you want to accept.

Creating your own token on Hive currently costs about $5 for a basic token (no staking) and $40–50 for a stake-enabled one. See hive-engine.com for the current price.

Custom lists

Custom lists let you carve out a group of users that get different rates from everyone else — family, friends, work contacts, paying subscribers, etc. Click + Add list.

A custom list — name it, drop usernames in, set this group’s rates

Give the list a name (e.g. family, work), enter the usernames comma-separated, and fill in the fee schedule. Lists higher in the priority order match first. You can create as many lists as you like.

Lists here are single 24/7 windows. Multi-time-window and day-of-week splits still live in rate-editor.html (known gap, on the roadmap).

Generate & post

The right-hand column — OUTPUT — Hive post body — shows the post that will be written to Hive. Press Generate to preview, Copy to grab the text, or Post to Hive to sign and publish via Hive Keychain. Use Load from Hive to pull your last announce back in for editing.

A filled-in example — rates set, a custom “fwend” list added, default fallback rates entered

Other sections on the same page — Nostr, Bitcoin, Lightning, SSH public key — work the same way: tick include, fill in the fields, and they join the post. Leave them off and they emit nothing.

Federation — one network, many servers

Federation is optional. Turn it on and users on your server can see, call and invite users on the other federated servers you trust. The same Hive identity works everywhere — @alice@v4call.com and @alice@hive-book.com are the same person on Hive.

Federation today runs over WebSocket. Nostr federation is on the roadmap and is currently disabled while the cross-fed media wrappers are being unified onto a single transport.

Escrow platform fee

Each server may take a small percentage of escrow transactions as a platform fee. The fee is set by the operator and varies per server.

Test serverApproximate platform fee
v4call.com~1%
hive-book.com~2%

Approximate values during testing. The canonical fee for each server is in its announcer post on the Hive blockchain. Self-host operators: set yours via the DEFAULT_PLATFORM_FEE environment variable in v4call’s compose file.

Note on swap.* tokens. Wrapped tokens such as SWAP.BTC can in principle be used to pay rates. At the moment the minimum increment hasn’t been fine-tuned, so the practical minimum is around 0.001 SWAP.BTC. Smaller increments are believed possible but not yet wired up.

Sibling projects

v4call started as one project; two pieces grew alongside it because they made the rest of the stack possible. Both are MIT licensed.

Storage

IPFS-Gate

A Hive-payment-gated IPFS pinning service. Operators run a node; users pay on-chain for upload + TTL. End-to-end encryption happens in the client (v4call) — the gate never sees plaintext.

Status: very early concept stage. First production use case is v4call attachments. Roadmap includes configurable TTLs, multiple payment tokens, per-operator quotas and richer admin tooling.

Relay trust

nGate

A Hive → Nostr relay-whitelist bridge. nGate scans Hive for server announces, verifies the operator’s cryptographic proof, applies economic gates (e.g. “escrow account holds at least 300 HP staked and/or delegated”), and updates the Nostr relay’s allow-list on a schedule.

Modes: flat (one account check) or split (escrow account + token account, combined with AND/OR). Miss-counter grace period before eviction; dry-run is the default. Sidecar to nostr-rs-relay.

Both projects exist because v4call needs them: IPFS-Gate gives users a pay-to-pin storage option that doesn’t depend on a single SaaS; nGate makes it possible to know which federation peers are economically committed before trusting them.

Run your own server

v4call ships as a Docker compose stack. The deploy walkthrough used for the current test servers is here: completenoobs.com/noobs/V4call-v0.11 (written against v0.11; the steps still apply to the current version).

From scratch in your project directory:

git clone https://github.com/CompleteNoobs/v4call
cd v4call
docker compose build --no-cache
docker compose up -d

Point a domain at the box (for example call.yourdomain.com), put your operator settings in the compose env block, and you have a v4call server. Federate with others by adding them as peers, or stay local — both are supported.

Trading pair for the test token used in demos: hive-engine.com/trade/TEST.
