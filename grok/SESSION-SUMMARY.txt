OVERALL FEDERATION HEALTH ASSESSMENT
================================================================================

Strengths (preserve these):
  - Extremely clean separation between payload transport (WS) and
    visibility (Nostr).
  - Consistent recipient-side enforcement (design rule #15) across
    DMs, attachments, room invites.
  - Defensive coding in nostr-fed.mjs (never crashes the main app).
  - Promise queue on federation sockets prevents ordering races.
  - Domain tiebreaker is simple and effective.
  - Persistence model (data/ bind mounts) is consistent after the
    v0.16.15 lesson.
  - The three latent bug classes surfaced by Phase D testing were
    all closed with good meta-rules captured in the docs.

Current state:
  - WS federation is mature and has carried real paid cross-server
    traffic (DMs + attachments + calls + rooms) across multiple
    production servers.
  - Nostr Phases A–D are fully shipped and integrated (discovery
    seconds instead of 2h, presence additive to WS).
  - The original "users sometimes don't show across servers" problem
    is solved.
  - The "visible via Nostr but actually unreachable" footgun is
    mitigated by recipientStatus + dm-precheck + clear messaging.

Remaining risk:
  - Mostly low. One medium item (call initiation should have the
    same precheck guard as DMs before Keychain prompts).
  - A few nice-to-have observability and liveness improvements that
    only matter at larger scale.

The federation is in a healthy, battle-tested state for its current
user base (small number of cooperating operators).

================================================================================
KEY META-RULES CAPTURED (FOR FUTURE WORK)
================================================================================

From the recovery notes and code review (repeat these to any new
contributor):

1. Recipient's home server is the only one trusted to enforce the
   recipient's policies. Caller server = courier + witness only.

2. Nostr is for visibility + discovery. WS is for everything that
   moves value or requires real-time signaling. Never conflate them.

3. Approval is the operator's "I want to interact" signal. Every
   user-facing surface (lobby presence, callable handles) must gate
   on it. Discovery can be independent.

4. When a signed canonical payload can conditionally grow (the
   Option B Nostr trailer), the signer and every verifier must stay
   byte-for-byte identical. Cross-reference the two implementations.

5. New additive federation message types are silently dropped by
   older peers. Plan coordinated rollouts for features, not just
   bugfixes.

6. Any change that gates loading of persisted approvals on "federation
   currently enabled" will re-create the v0.16.15 surprise.
